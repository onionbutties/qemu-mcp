# QEMU MCP Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a stdio MCP server that wraps the existing QEMU controller so a model can drive the VM through typed tools, with screenshot output reduced to OCR/ASCII text wherever possible.

**Architecture:** A Node ESM MCP server (`scripts/mcp/server.mjs`) owns one `VmSession` that wraps `scripts/lib/qemu.mjs`. Tool modules register VM lifecycle, monitor/QMP, input, screen, disk, and macro tools. Screen tools internally run screenshot -> PPM -> PNG -> OCR/ASCII and return text; raw PNG is available on demand. Disk tools read and build FAT12/FAT16 images without booting. Monitor access is serialized. No QEMU source changes.

**Tech Stack:** Node.js ESM, `@modelcontextprotocol/sdk`, `zod`, existing `scripts/lib/*` and `tools/*`, Node built-in test runner.

**Spec:** This file is the spec for the first slice. Subsequent macro definitions live in `scripts/mcp/macros/*.mjs`.

## Global Constraints

- Node ESM (`.mjs`), Node >= 20.
- QEMU binary stays `C:\Program Files\qemu\qemu-system-i386.exe`; monitor port default `5555`.
- MCP server is stdio; diagnostic output goes to stderr only.
- One VM session per server process.
- Tests run with `node --test tests/mcp/*.test.mjs` (and `tests/fat/*.test.mjs` where applicable).
- Do not modify QEMU or installed SDK packages.
- All file paths are relative to repo root `D:\_oblocal\stuff\wfw` unless absolute.

## Review Focus

- VM not running: every VM-dependent tool must return a structured `{ ok: false, error }` result rather than throwing.
- Monitor disconnect mid-session: `VmSession.status()` must report `running: false` and commands must fail gracefully.
- OCR returns empty text on graphical screens: `wait_for_text` must time out and return the last captured text, never hang.
- FAT paths use either `/` or `\` and mixed case: list/read must normalize and compare case-insensitively.
- Screenshot filenames must be unique to avoid overwriting concurrent captures.
- Monitor commands must be serialized across concurrent tool calls.
- Raw screenshot image content can be large; keep it optional and behind `screenshot`.
